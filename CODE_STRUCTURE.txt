   ├─ POST Handler
   │  ├─ Input: { chatId, prompt, provider?, stream?, systemPrompt? }
   │  ├─ Flow:
   │  │  1. Authenticate user
   │  │  2. Load message history from MongoDB
   │  │  3. Append new user message
   │  │  4. Save user message to MongoDB
   │  │  5. Check if first message → generate title

   │  │  7. Handle streaming or collect response
   │  │  8. Save assistant response to MongoDB
   │  │  9. Return response + metadata
   │  └─ Output: { content, chatId, messageCount, provider, streaming }

================================================================================
MONGODB SCHEMA
================================================================================

Collection: stage2_chats
├─ _id: String (chatId, converted from ObjectId)
├─ userId: String
├─ title: String (auto-generated or "New Chat")
├─ messageCount: Number
├─ createdAt: Date
└─ updatedAt: Date

Collection: stage2_messages
├─ _id: ObjectId
├─ chatId: String (foreign key to stage2_chats._id)
├─ userId: String
├─ role: String ("system" | "user" | "assistant")
├─ content: String
├─ sequenceNumber: Number (0 for system, auto-increment for others)
└─ createdAt: Date

Indexes (Recommended):
├─ stage2_chats: { userId: 1, updatedAt: -1 }
└─ stage2_messages: { chatId: 1, userId: 1, sequenceNumber: 1 }

KEY ARCHITECTURE PRINCIPLES
================================================================================

1. STATELESSNESS
   └─ HuggingFace has NO memory between requests
   └─ Context comes from the request body
   └─ Solution: Send full conversation history

2. CONTEXT REBUILDING
   └─ Every request loads messages from MongoDB
   └─ Full history is sent to LLM with each request
   └─ Model appears "aware" because it sees conversation

3. DATABASE AS SOURCE OF TRUTH
   └─ MongoDB is the ONLY persistent store
   └─ No in-memory variables
   └─ Multiple servers/processes work together

4. USER ISOLATION
   └─ userId filter on all queries
   └─ No cross-user data access
   └─ GDPR compliant

5. MESSAGE ORDERING
   └─ sequenceNumber maintains chronological order
   └─ Always query with ORDER BY sequenceNumber
   └─ Race conditions don't affect order
